# 研究：Samsung 半导体缺陷 Agent

这篇笔记记录了设计灵感以及 FabPilot 与之分歧之处。它基于三星半导体缺陷分类工作的
**公开描述**；FabPilot 不包含任何三星源代码，也不复刻任何专有模型。

## 我们从公开资料中学到了什么

三星的半导体缺陷 agent（据称与高带宽内存（HBM）/ 芯片制造相关）
被描述为结合了：

1. 缺陷显微图的**逐图像、逐晶圆分割 + 缺陷分类**，
   用于确定哪些晶圆需要优先复查。
2. **假设驱动的工作流** —— 操作员提出一个假设，系统收集证据来
   证实或反驳它，而不是盲目地对每个缺陷进行排序。
3. **一个反馈回路**，把发现的缺陷回灌到分类 / 复核流水线中，
   使系统随着已标注样本的积累而不断改进。

反复出现的主题是 *假设优先的分诊*：先提出一个假设来缩小搜索空间，
再让证据来决定。

## FabPilot 借鉴了什么（概念层面）

FabPilot 把 **假设驱动的推理模式**（而非视觉模型）移植到
工业时序诊断中：

- 用户任务描述一个症状（例如「ETCH-01 的 gas_flow 漂移」）。
- **诊断 Agent** 生成显式的假设，并通过工具（滞后分析、
  相关性、维护历史、相似案例）收集证据。
- 确定性的 **假设-证据记忆** 让每个假设依次经历
  `candidate → active → supported / refuted / inconclusive`。
- 证据被*关联*到假设上并*重新评估* —— 同样的
  证实/反驳循环，只不过作用于遥测数据而非显微图。

## FabPilot 有意分歧之处

| Samsung（公开描述） | FabPilot |
|---|---|
| 视觉：缺陷显微图分类 | 时序：传感器遥测、报警、维护 |
| 由操作员提出假设输入 | Supervisor + 诊断 Agent 共同生成假设 |
| 面向晶圆的缺陷优先级分诊 | 面向假设的根因排序 |
| 专有视觉模型 | 可插拔的时序预测模型（PatchTST、iTransformer、统计基线等） |
| （公开资料未详述） | 在共享状态中的完全开放、可审计的 ReAct 轨迹 |

## 为什么「假设优先」对诊断很重要

一个把每个统计量都倾泻到症状上的朴素 agent，会被相关通道淹没。
假设优先的分诊要求*首先*提出一个候选的因果叙事，然后用有针对性的证据来验证。
这就是为什么 FabPilot 把相关性当作假设的**证据**，而绝不会单独当作因果 ——
正是这种自律让三星所报道的系统避免过度信任分类器的置信度。
